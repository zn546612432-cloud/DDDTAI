# 重构迁移与验收

当前阶段：架构登记完成；下列运行实现与应用迁移均待完成。此清单是验收范围，不是已完成功能表。

## 实施顺序

1. 建立命令、事务、事实和存档核心；建立事件分类和配置校验。
2. 实现唯一时间推进规划器，接入短充/长充/自然走时、补电与耗电；测试准确阻挡点和期限。
3. 实现跨渠道消息领域；迁入 D01 特殊输入、D02–D05 日常、固定主线、Flow、旧预设、AI 与邀请。
4. 迁入委托和账本领域；替换较早日期专有 runner，保留批准的特殊玩法。
5. 接入朋友圈、日记、备忘录与文件等事实依赖；清除由旧 UI 直接推断的剧情结果。
6. 逐 App 接入既有界面、路由和素材；不改变已确认 UI。
7. 接入开发者配置、诊断、导入和版本迁移；运行旧项目行为回归和新增跨领域验收。
8. 所有项目通过后发布独立完整预览；保留 BBBTAI，明确切换入口后 DDDTAI 成为后续开发目标。

## 必须复现并修复的旧入口

- D02 机房升级直接插入两条 me 台词。
- chat-delay 会话离开后停止计时，昨天内容今天打开还重新等待。
- 旧预设一次插入多条气泡，却只建立一个通知。
- Flow、D01 联系人、主线原生对话和 AI 自行管理写入/未读/延迟。
- 聊天 mandatory 与充电 gateDay 互不构成完整统一约束。
- 主线开放日、期限、具体触发时点与禁止补电混用。
- 各天委托各自处理阶段、奖励、邮件和验收。

## 最低验收矩阵

| 场景 | 必须成立 |
|---|---|
| 当前聊天连续多条 | 每条按间隔到达；人物、日期、未读一致 |
| 昨天/多天未读 | 一次补历史；不刷旧横幅，不代发熙蒙 |
| 当天/隔天/多日迟回 | 根据时间和已经解决的事实选择台词 |
| 晚饭已错过 | 未响应收尾；不能补出赴约或合照 |
| 主线当天未完成 | 不越过阻挡点，不假完成；仍可打开手机实际入口 |
| 跨日限期部署 | 截止前可推进；截止点未完成才阻挡 |
| 短充跨主线 | 停在最近强制边界；补电许可单独判定 |
| 长充跨主线 | 与自然推进使用同一个阻挡决定，不从另一入口漏过 |
| 一次跨多个事件 | 按因果顺序处理，仅允许成立的结果 |
| 主线邮件送达 | 不能等同部署成功；必须读/回复的节点验证对应操作 |
| 可选委托逾期 | 正确过期；不自动通关、提交和付款，不阻塞无关主线 |
| D01 | 必接单、实际处理与结算；自由首句及三条追问特殊规则保留 |
| D55 | 录音真实播放结束后才能推进；终章充电与换视角不被通用跳日绕过 |
| 页面后台/刷新 | 后台不补走剧情时间；不重复消息、收益、奖励 |
| 开发者重建 | 显式测试状态、先备份；不能影响正常短充权限 |
| AI 权限 | 只读授权的已发生内容；不得读取日程 App、未来剧情、未发草稿 |
| 所有 App | 保持已确认外观、返回/手势与素材，不出现新的游戏任务板 |
| 存档迁入 | 旧记录和账户不丢；失败可保留原文件并回退 |
